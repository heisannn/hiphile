# デザインのガイド

`next/` の画面をデザインするとき、レビューするときに読む。AntiWebUI と `anti-webui-md3e`（以下 md3e）で
Material 3 Expressive にデザインし直す Hiphile を、詰まったデスクトップのプレーヤーとして保つための決まりを
書く。何をどう作るかは [UI を AntiWebUI に移す](migration.md)が決め、コードの書き方は
[コーディングのガイド](coding-guide.md)が決める。`crates/` の GPUI 版は今までどおり gpui-kit のガイドに従う。

「しなければならない」は正しさや約束のための制約で、「する」は既定、外れるには具体的な理由が要る。「してよい」は
任意の手。部品の細かい振る舞いと値は、AntiWebUI のリビジョン `25e82a1` のソースと `docs/design/`（特に
15〜20）が正しい。

## 考え方

詰まった、静かで、正確なデスクトップのプレーヤーにする。表現は再生を伝えるところに使い、ライブラリの長い
ところは詰めたままにする。

1. **明快さが先。** 主な作業と次の操作がはっきりしてから、表現を足す。
2. **組み合わせが先。** md3e の部品を組み合わせて Hiphile の作業を作る。新しい部品は、振る舞いが本当に
   新しいときだけ作る。
3. **トークンが先。** 色、文字、形、動きは md3e のトークンから取る。テーマの外に色のリテラルを書かない。
4. **デスクトップの約束が先。** キー操作、メニューバー、コンテキストメニュー、詰まったリスト、大きさを
   変えられるペイン、ずっと見えている移動先は、md3e のモバイル向けの既定より先に守る。
5. **状態は見えるようにする。** ホバー、フォーカス、選択、無効、読み込み、検証、取り返しのつかない操作の
   状態は、どの画面でも同じ見た目で示し、互いに見分けられるようにする。
6. **形は包む関係を表す。** 角の丸み、内側の余白、境目は、重なっても 1 つの階層として読めるようにする。
7. **フィードバックは本当のことを表す。** 読み込み、ツールチップ、動きは、実際の状態か移り変わりを
   伝えるときだけ使う。すぐ終わる操作に儀式を足さない。

### md3e のモバイルの癖をそのまま持ち込まない

| モバイルの癖 | Hiphile の既定 |
| --- | --- |
| 56 dp と 72 dp のリスト項目をどこにでも | 長いリストは Hiphile の行の寸法（カバー付きで 48 px）。md3e のリスト項目は設定と短いリストだけ |
| 画面ごとに大きく畳まるアプリバー | 小さなアプリバー（64 px）を固定。長いリストの上に大きく畳まるバーは置かない |
| 下のナビゲーションバー | 左の `wide_navigation_rail`。狭いウィンドウでは畳む |
| ボトムシートで選ぶ | メニュー、ポップアップ、ダイアログ |
| 長押しで出す操作 | 右クリックのコンテキストメニューと、同じコマンドのキーとメニューバーの項目 |
| 指で押す前提の、ホバーの無い大きな的 | ホバーの状態レイヤーを持つ部品。的は詰まった画面でも押しやすい大きさにする |
| 画面の遷移で全体をスライド | 薄く現れて少し上がって入る。すぐ終わる操作では何も動かさない |
| すべてを FAB で始める | 検索を開くレールの FAB だけ。再生は詳細のヘッダーの `extended_fab` |

## 作業から始める

画面を描く前に書き出す：

- 利用者の主な作業
- 見ているもの、変えるもの（アルバム、アーティスト、曲、プレイリスト、キュー、サーバー、設定）
- すぐに使えなければならない操作
- 決めるのに要る情報
- 空、読み込み中、失敗、オフライン、権限の無い状態
- 作業を通すキーの道筋

ウィンドウはその答えに沿って組む。ダッシュボードの格子や部品の見本帳から始めない。画面は利用者の頭の中の
もの（ライブラリ、再生中の曲、キュー）を見せ、コアやサーバーの作りを見せない。

主な作業から先にデザインし、そのあとで操作を配る。重みと場所と情報の深さは、その作業の大事さに合わせる。
主な結果を、隅の小さな数やアイコンや弱い操作に押し込めない。

操作を 1 つ足すたびに、それが何に対して、今どんな状態で、どの範囲に、何を起こすかを言えるようにする。
画面がそれを見せていないか、はっきり示していないなら、その操作はまだ早い。コアにできることだからという
だけで出さない。

## トークン

### 色

- 配色は md3e の `ColorScheme` を種の色から `SchemeVariant::Content` で作る（`next_ui::theme::scheme`）。
  種は再生中の曲のカバーで、アプリ全体がその配色に従う。Appearance で固定の色を選べるようにするのは
  まだ（migration.md の「進み具合」）。
  曲が変わると `motion::slow_effects` でクロスフェードする（`next_ui::theme::follow_theme`）。何も再生して
  いない間は `DEFAULT_SEED`。
- Light、Dark、System は今と同じ。System はシステムの外観に従う。
- 色は役割で使う：

  | 役割 | 使うところ |
  | --- | --- |
  | `surface`、`on_surface` | ウィンドウの地とその上の文字 |
  | `surface_container` | 画面のペイン |
  | `surface_container_low` | キューのペイン、メニュー |
  | `surface_container_high` | ダイアログ、設定のポップアップ、検索のバー |
  | `on_surface_variant` | 詳細、補いの文字、選んでいないタブ |
  | `primary`、`on_primary` | 既定の決定、選択の強調、再生ボタン |
  | `secondary_container`、`tertiary_container` | レールの目印、選んだメニューの項目など、部品が決めたもの。選んだ行とカードの塗り |
  | `error`、`error_container` | 失敗と検証のエラーだけ |
  | `outline`、`outline_variant` | 枠線と区切り |
  | `scrim` | ダイアログとポップアップの後ろ |

- 状態の色を飾りに使わない。意味を色だけで表さない（アイコン、文字、形も添える）。
- 色のリテラルを書くのはテーマ（`next_ui::theme`）と、色そのものがデータであるもの（カバーの絵）だけ。
  役割が足りなければテーマに足す。
- どの面も、ライトとダークと、色の違う何種類かのカバーの配色で確かめる。地が白、文字が黒とは決めつけない。
  カバーから作った配色は彩度も明るさもまちまちになる。

### 文字

- md3e の `TextStyle` の段階を Roboto Flex で使い、日本語はシステムのフォールバック（`LANG` を入れたうえで
  Hiragino Sans）にする。
- まずは次のとおり：

  | もの | 段階 |
  | --- | --- |
  | アプリバーの画面のタイトル | `TITLE_LARGE`（`next_ui::app_bar`） |
  | ページの見出し（サインインなど） | `HEADLINE_SMALL` |
  | 行のタイトル | `TITLE_SMALL` |
  | 詳細、補い | `BODY_MEDIUM` を `on_surface_variant` で |
  | ウィンドウの地の文字 | `BODY_MEDIUM`（`next_ui::type_scale::body`） |
  | エラー | `BODY_SMALL` を `error` で（`next_ui::type_scale::error_text`） |
  | 歌詞の行 | `HEADLINE_LARGE` |

- 段階を増やすより、大きさ、太さ、余白、区切りで階層を作る。段階の外の大きさを作らない。
- 等幅はキーの表記と、揃えたい数（時間、曲番号）にだけ使う。日本語に大文字や字間を足さない。
- 可変フォントの `wght` は文字幅を変えるので、遷移には使わない。強調は色と不透明度で行い、ラテン文字にだけ
  `GRAD` を足してよい。

### 密度と寸法

- 長いリストは Hiphile の行の寸法を使い、今と同じ高さ（カバー付きで 48 px）にする。md3e の 56 px と 72 px の
  リスト項目は、設定と短いリストに使う。
- 密度は局所の文脈ごとに変え、1 つの部品だけを変えない。ツールバー、メニュー、表、長いリストは詰め、
  サインインのようなまばらなフォームはゆったりさせる。
- md3e の部品の大きさは `ButtonSize` などの段階で選ぶ。外の箱の高さだけを変えると、文字、アイコン、余白、
  的が一緒に変わらない。
- 繰り返す寸法には名前を付けた定数を置き、同じ関係は同じ定数から取る（レールの `TOP`、`NARROW_INSET`、
  `WIDE_INSET` のように）。

### 形

- 角の丸みは Material 3 の段階から選ぶ：4、8、12、16、20、28、丸。部品ごとに新しい値を作らない。
- ペインは大きな角（28）と余白のある `surface_container`。ダイアログと設定のポップアップも 28。
- 入れ子の面は同心に見せる。内側の丸み ≈ 外側の丸み − 間、に一番近い段階を選ぶ。
- `MaterialShape` は形に意味があるところだけに使う：再生ボタンの変形、読み込み（`loading_indicator`）。
- カバーは四角のまま、アーティストの写真は円にする。形では子を切り抜けない（d15:303）ので、角の丸みで
  切り抜く。
- 丸めた親が子を切り抜くとは決めつけない。中の面、選択の塗り、スクロールする中身にも丸みか切り抜きを
  与え、対照的な地の上で両方のテーマで確かめる。

### 動き

- md3e のばねを使う：`fast`、`default`、`slow` × `spatial`、`effects`（`motion::fast_spatial` など）。位置と
  大きさは `spatial`、色と不透明度は `effects`。
- 画面は md3e のショーケースと同じく、薄く現れて少し上がって入る。
- すぐ終わる操作では何も動かさない。

### アイコン

- Material Symbols Outlined だけを使う（`anti_webui_md3e::icons`）。Lucide と GPUI 版の SVG は持ち込まない。
- トグルでは `FILL` を動かす。選んだ移動先とタブは md3e が `FILL` を 1 にする。
- アイコンはラベルを補うもので、見慣れない操作をアイコンだけで当てさせない。アイコンだけのボタンには
  すべて `.access` で名前を付ける。

## 画面の各部

| 部分 | 決まり |
| --- | --- |
| ウィンドウの上端 | タイトルバーの帯は置かない。レールがウィンドウの上端まで伸び、信号機ボタンはレールの上の余白（44 px）に重なる。レールの上端とアプリバーはウィンドウを動かし、ダブルクリックで拡大する。そこに置いた押せるものは動かさない。「Hiphile」の文字は置かない |
| 移動先 | `wide_navigation_rail` の 6 項目：Home、Artists、Albums、Songs、Playlists、Favorites。広いウィンドウでは開き（220 px）、狭いウィンドウでは畳む（96 px）。ヘッダーにはレールを開け閉めするメニューのボタンと、検索を開く FAB（開いたときは extended FAB）。閉じたときに中が中央に来るよう、40 px の部品は左から 28 px、56 px の部品は 20 px に置く |
| サーバーと設定 | ウィンドウの右上。画面のアプリバーの右端に重ね、キューが出ている間はキューの見出しの右端に重なる。アプリバーはその幅をあけて、画面の操作と重ならないようにする。アバターの右端はペインの右端に揃える。設定はアイコンボタンでポップアップを開き、その右のサーバーの `initials_avatar` のボタンから md3e の `menu`（サーバーの一覧、Add Server…、Sign Out）を下に出す。レールの下端に置くと、最小の高さのウィンドウでレールが入りきらない |
| 画面の見出し | 戻ると進む、画面のタイトル、並べ替えを持つ小さなアプリバー（`next_ui::app_bar`）。絞り込みは一覧のペインの上に置く。長いリストの上に大きく畳まるバーは置かない |
| 画面の本体 | レールとバーから離した `surface_container` のペイン（角 28） |
| Albums、Artists、Playlists | `next_ui::list_detail` の一覧と詳細のペイン。一覧は決まった幅を保ち、残りを詳細に渡す（widgets の `split_row` は比率で分けるので使わない）。詳細のヘッダーは大きなカバーと、`button_group` に入れた `extended_fab` の再生とトーンのシャッフル |
| Home | どの棚も `next_ui::card_grid` のカードの 1 行と、曲の行。並びはコアの `sections()` のとおり。md3e の `carousel` は、キーとフォーカスが無く、外からスクロールできず、縦のホイールを取ってページを止めるので使わない |
| Songs | 詰めた行と並べ替えられる列の `row_list` |
| Favorites | md3e の secondary の `tabs` |
| 検索 | md3e の `search_bar` と、その下に付く結果。レールの FAB とキーで開く |
| プレーヤーバー | 下に付くツールバー。操作は `button_group` で、塗りの再生ボタンは丸と四角の間で形を変える。位置は再生中は波が流れ、一時停止中は平ら。音量は普通のスライダー。キューと歌詞は `icon_toggle_button` |
| キュー | `surface_container_low` の右のペイン。ドラッグとキーで並べ替える |
| 歌詞 | ウィンドウ全体に出す。点いた語は色と不透明度で示し、ラテン文字には `GRAD` を足す。カバーはバーから飛ぶ |
| サインイン | レールは出さない。枠線のテキストフィールド、表示を切り替えられるパスワード、塗りのボタン |
| 設定 | 同じウィンドウのポップアップ。`surface_container_high` で角 28、ウィンドウに合わせて広げる。左にページの一覧、右にそのページ。グループは `segmented_list`。スイッチ、`dropdown_field`、ラジオボタン、中央を起点にしたバランスのスライダーを行の後ろに置く。Escape と scrim で閉じる |
| 通知 | `snackbars`。元に戻すものは `lasting` で時間を付ける。同期の進み具合は一覧のペインの見出しの `circular_progress` |
| 長い名前 | はみ出しは切って右端を薄くする。「…」は出ない |

## 何にどの部品を使うか

| 目的 | md3e の部品 | デスクトップでの決まり |
| --- | --- | --- |
| 決定の場の既定の決定（Enter で走るもの） | `ButtonStyle::filled()` | 1 つの決定の場に 1 つ。操作が 1 つしかない、よく使う、右上にある、というだけで塗りにしない |
| 普通の操作 | `tonal()`、`outlined()` | 境目が要るかで選ぶ |
| 静かな操作 | `text()`、`icon_button` | ツールバーと行の中 |
| アイコンだけの操作 | `icon_button`、`styled_icon_button` | よく知られた記号だけ。`.access` で名前を付ける |
| オンとオフを持つアイコンの操作 | `icon_toggle_button` | キュー、歌詞、パスワードの表示、お気に入り。オンは `FILL` で見せる |
| 並んだ操作 | `button_group` | プレーヤーの操作、詳細の再生とシャッフル |
| 1 つを選ぶ並び | `connected_button_group`、secondary の `tabs` | 選んだものはずっと見えている |
| 画面で一番の操作 | `extended_fab`、`fab` | 検索と、詳細の再生だけ。どの画面にも FAB を置かない |
| 移動先 | `wide_navigation_rail` | ほかの場所に移動先の並びを作らない |
| 画面の見出し | `next_ui::app_bar` | md3e の `TopAppBar` は戻ると進むを並べられないので、画面では使わない |
| ボタンから出る操作の一覧 | `menu`、`styled_menu` | 開いている間、出したボタンは押された見た目のまま |
| 右クリックの操作 | `menu` をポインタの位置に出す | それしか道の無い操作にしない |
| すぐ効く設定 | `switch` | 行の後ろに置く |
| 少ない選択肢を見せて選ぶ | ラジオボタン | |
| 多い選択肢から選ぶ | `dropdown_field` | |
| 数を選ぶ | `slider` | バランスは中央を起点にする |
| 文字を入れる | `outlined_text_field` | 見えるラベルを付ける。エラーは `supporting` でフィールドの下に |
| 短い決定、短いフォーム | `dialog` | 失敗しても開いたまま |
| 取り返しのつかない操作の確認 | `alert_dialog` | 元に戻せるものには使わない |
| 待たない知らせ、元に戻す | `snackbars` | 元に戻すものは `lasting` |
| 短い説明、ショートカット | `tooltip` | 見れば分かることを繰り返さない |
| ペインの読み込み | `loading_indicator` | |
| 部品の中の読み込み | `circular_progress`、`indeterminate_circular_progress` | |
| 進み具合 | `linear_progress` | |
| 同じ種類のものの面 | `clickable_card`、`filled_card` | カードの中にカードを入れない |
| 設定のまとまり | `segmented_list`、`list_item` | |
| 人とサーバー | `initials_avatar`、`avatar` | |

標準の部品は、その意味の役割で使う。メニュー、ドロップダウン、ポップアップ、検索はそれぞれ違う選択、
フォーカス、キー、閉じ方、配置の約束を持ち、取り替えのきく箱ではない。md3e の部品の見た目が合わない
ときは、`*_with`（`slider_with` など）で標準の振る舞いに自分の見た目を載せる。似た見た目を `div` で
作り直さない。

## 配置

### 階層

段階は少なくはっきりさせる：画面のタイトル、節の見出し、本文、補いの文字、ラベル。色や容器を足す前に、
大きさ、太さ、余白、区切りを使う。

レビューでは色と飾りを消して見る。それでも主な作業、今の選択、結果、次の操作が構造から分かるように
する。強調は限られた予算で、1 つの面には 1 つの焦点を置く。

### 余白の関係

余白は関係を表す。2 つのものが互いに何であるかで間を選ぶ。

| 関係 | 目安 | 例 |
| --- | --- | --- |
| 見た目の補正 | 2 px | アイコンのベースライン |
| 1 つの部品の部分 | 4 px | メニューのアイコンとラベル、タイトルと詳細 |
| 近い部品どうし | 8 px | ダイアログの操作 |
| 1 つのまとまり | 12 px | 行の列、詰めたフォームの行 |
| 1 つの節の別のまとまり | 16 px | ペインの内側、フォームのまとまり |
| 別の節 | 24 px | ページの大きな塊 |
| 大きな境目 | 32 px | 空の状態の周り |

- 部品の内側の余白は部品のもので、部品どうしの間は親のもの。
- 縦の間でまとまりを示す。同じ間は同じ関係に見える。
- 繰り返す行では、アイコン、ラベル、値、後ろの操作を同じ列に置く。
- 余白を二重にしない。余白のあるペインに置くカードに、もう一度ペインの余白を足さない。
- 見た目の補正は 1〜2 px だけで、なぜ違うかをコードに書く。

### 揃える線

面ごとに少数の揃える線を決める：先頭と末尾の端、文字のベースライン、中心線、決まった列。同じ段のものは、
種類が違っても同じ線に付ける。

- 兄弟の面は同じ内側の余白を共有する。同じ段の見出し、ツールバー、行、空の状態に、少しずつ違う先頭の端を
  作らない。
- 列の形を見出しから行、読み込み中、編集中まで繰り返す。
- 字下げは本当の階層だけに使い、入れ子が終わったら親の線に戻る。
- アイコン、詳細、後ろの操作が無い行でも、残りのラベルを動かさない。
- 同じ段の大きな面（レールのヘッダー、画面のタイトル、ペイン、プレーヤーバー）は続いた線になるようにする。
- 等しくしたい端や間が 1 px 違うのは欠陥。測って確かめ、ずれは同じ値の持ち主を直して消し、px の補正を
  足さない。
- 大きさの違う文字が並ぶ行はベースラインで揃える。数は右に揃え、名前と文は左に揃える。
- アイコンは決まった幅の枠の中央に置く。
- 区切りの線は境目の持ち主が描き、隣り合う 2 つが同じ線を描かない。
- スクロールバーはスクロールする面の端に付ける。中身の余白で面の中ほどに引き込まない。

### ペインの大きさ

- 中身の要るものから決め、役割の違うペインを半分ずつにしない。
- 一覧と詳細では、一覧が見渡せる幅を保ち、残りを詳細に渡す。
- 大きな面ごとに 3 つの大きさを決める：作業ができる最小、心地よい既定、余りをどう使うか。利用者が変えた
  分け方は保存し、戻すときは今のウィンドウに収める。
- 一番強い高さは一番上の決定の層に取っておく。同じ層の中では地の色と線で階層を示す。

### 狭いウィンドウ

ウィンドウは最小 900×560 まで狭まる。狭まるときの順を決める：

1. 主な作業を残す
2. 大きさを変えられる面を決めた最小まで縮める
3. 補いのラベルとペインを畳む（レールは 1000 px より狭いと畳む）
4. あまり使わない操作をメニューに移す
5. はみ出した面だけをスクロールさせる

操作を隠すときは別の道を残す。リストや本文だけがはみ出すとき、ウィンドウ全体をスクロールさせない。

## 状態は見えるようにする

### 押す前に結果が分かる

部品は結果を予告する。ラベルは操作と対象を名乗り、状態は使えるかを示し、フィードバックは同じ結果を
確かめる。押されたらすぐ応え、長い仕事の間は二度押せないようにし、結果は変わったもののそばに見せる。
結果が見えないときだけ、成功を知らせる。

| 状態 | 決まり |
| --- | --- |
| 休み | はっきり押せると分かり、うるさくない |
| ホバー | md3e の状態レイヤー。それだけを手がかりにしない |
| 押下 | すぐ見える。md3e の部品は形も変わる |
| 開いている | ボタンから出したポップアップが開いている間、ボタンは押された見た目のまま |
| フォーカス | キーのフォーカスがはっきり見える |
| 選択 | ホバーと違う、ずっと残る見た目 |
| 無効 | 弱め、ホバーと押下に応えない |
| 読み込み | 文脈を残し、二度押せず、長い待ちは説明する |
| エラー | 何が起きたか、どう戻るかを言う |

- 選択は情報の一部。タブ、移動先、選べる行、絞り込みはずっと選んだ状態を見せる。
- 選んだ移動先、行、タブは、その項目自身の面で示す：md3e の目印、塗り、強い文字の色。先頭の端の棒や片側の
  枠線を選択の印にしない。
- 選んだ行とカードは `secondary_container` で塗り、そのリストにフォーカスが無い間は塗りを弱める。弱めても、
  ホバーの灰色の状態レイヤーと見分けられる色味を残す。文字の色は選んでも変えない。md3e の
  `on_secondary_container` は詳細の `on_surface_variant` より弱く、タイトルが詳細より薄く見えるため。
- 取り返しのつく操作とつかない操作を分ける。取り返しのつくものは元に戻すスナックバーにし、取り返しの
  つかない重い操作だけを `alert_dialog` で確かめ、その対象と結果を名乗る。

- キーのフォーカスは md3e の輪（`secondary` の 3 px）で示す（`next_ui::focus_ring`）。一覧とグリッドでは
  フォーカスを持つのは一覧で、キーのいる項目が自分の縁の内側に輪とフォーカスの状態レイヤーを出す。輪は
  Tab かキーでフォーカスが来てから出し、ポインタで押すと消す。いくつ選んでいても、輪はカーソルの 1 つだけ。

### ポインタ

押せるものは、md3e の部品と同じく指の形（`CursorIcon::Pointer`）にする。ボタン、タブ、移動先、スイッチ、
リストの項目、カードがそう。自分で作る押せるものも揃える。テキスト、リサイズ、掴む形は、その操作が
できるところだけ。

ホバーの効き目は控えめにする。取り返しのつかない操作や欠かせない操作を、ホバーでしか出さない。

### コマンドを置く場所

- 主な操作、よく使う操作は、ラベルの付いたボタンか見慣れたツールバーの部品として見せておく。
- 今の面の補いの操作は、見えるボタンから出す `menu` に入れる。
- ポインタの下のものに対する操作は、コンテキストメニューに入れる。
- 大事なコマンドはキーとメニューバーの項目でも使えるようにする。メニューバーにあるキーはアプリ全体の
  コマンドで、それ以外のキーは `next-ui` のキーマップが受ける。今のキーマップは仮なので、新しく決める。
- ホバーで出るアイコンは、ほかの場所でも使えるコマンドの近道としてだけ置く。
- 1 つのコマンドは、どこに出ても同じ動詞、アイコン、キー、有効かどうか、結果にする。
- 画面を少なく見せるために、何でもメニューに入れない。

### ボタンとリンク

アプリの状態を変える、決定を確かめる、道具を開く、送る、コマンドを走らせるものはボタンにする。
下線のリンクは外のもの（URL、ウェブのページ、メールアドレス）だけに使う。アプリの中の移動先（行、カード、
タブ、レール）はその部品かボタンで開く。静かに見せたいコマンドは `text()` かアイコンボタンにし、リンクの
見た目にしない。

## フィードバックとオーバーレイ

決定に合う一番小さな面を選ぶ：

- ツールチップ：短い説明かショートカット
- メニュー：操作の短い一覧
- スナックバー：決定の要らない、待たない知らせ
- ダイアログ：1 つの決定か短いフォーム
- アラートダイアログ：重い操作のはっきりした確認
- ポップアップ（設定）：同じウィンドウの中の、場所の要る作業

ツールチップは足りない意味を補うもので、見れば分かる操作を繰り返さない。見慣れない記号、はっきりしない
範囲、ほかで見えないショートカットにだけ付ける。

オーバーレイを重ねない。Escape は一番上の閉じられる層を閉じ、フォーカスは開いたものか、次の筋の通る場所に
戻る。md3e のダイアログは開くとフォーカスを移し、Tab を中に閉じ込め、閉じると元に戻す。自分で作る
オーバーレイ（設定のポップアップ）も同じにする。

オーバーレイの操作は、そのオーバーレイが見せているものか状態を指さなければならない。使えない操作は隠すか、
使えない理由が分かるように無効にする。

失敗したダイアログは閉じず、入れたものを残し、エラーを決定のそばに見せる。

## 動きで変化を説明する

動きは変化を説明するもので、飾りではない。出る、消える、広がる、場所がつながる、に短い移り変わりを使う。
大きなレイアウトの変化は、不透明度や変形で同じ関係が伝わるならそちらを使う。動きが無くても状態が分かる
ようにし、どの部品にも既定の動きを足さない。

- 動きを減らす設定には、Hiphile の動き（カバーの飛行、歌詞のスクロール、配色のクロスフェード）が従う。
  md3e の部品の動きは止まらない。
- 途中で遮られた動きは、今の値から滑らかに戻る。古い終点からやり直さない。
- 関係するものの間をポインタやスクロールが動く間は、プレビューの面を保ち、中身や位置をその場で変える。
  変わるたびに消えて出直すとちらついて見える。

## データの多い画面

詰まっていても窮屈にしない。リスト、表、検索の結果、キューでは：

- 見出しと行の主な名前を動かさない
- 比べる値を揃え、数には等幅の数字を使ってよい
- フォーカス、ホバー、今の行、複数の選択を見分けられるようにする
- 並べ替えと絞り込みを見えるように、戻せるようにする
- 選択は曲の ID で持ち、並べ替えと絞り込みをまたいで保ち、見える位置までスクロールする
- 長いものは見えている行だけを作り、キー操作の意味を変えない
- 空の状態は次の操作を示す

同じ欄を比べるなら表、まちまちなものを見渡すならリスト、本当の階層なら木を選ぶ。複雑なデータの部品を
見た目のために使わない。

### 曲の行

曲を並べるところ（アルバムとプレイリストの詳細、Songs、Favorites、Home とアーティストの上位曲、キュー）は、
どこでも `next_ui::song_row` の 1 つの形で描く。画面ごとに行を組み立てない。

- 並びは「番号 → カバー → 曲名と詳細 → 再生中の印 → 長さ → ハート → More」。番号とカバーはその画面に
  あるときだけ置く。ほかの列は、中身の無い行でも同じ幅を空けておき、後ろの列を動かさない。
- 番号は 4 桁の入る列（`NUMBER_LANE`）に右揃えにする。再生中の曲でも番号は番号のままで、再生中の印は
  印の列（`PLAY_STATE_WIDTH`）に出す。
- 曲名は `TITLE_SMALL`、その下の詳細（アーティスト、アルバム）、番号、長さは `BODY_MEDIUM` を
  `on_surface_variant` で。行によって段階を変えない。
- 長さは `h:mm:ss` の入る列（`DURATION_LANE`）に右揃えにする。
- ハートと More は行の後ろの列（`next_ui::row_buttons`）に置く。メニューとキーの近道なので、ポインタが
  乗っている間、選んでいる間、その行のメニューが開いている間だけ見せる。お気に入りの塗ったハートは状態を
  表すので、いつも見せる。隠れている間も場所は残す。Favorites のアルバムとアーティストの行も同じボタンを
  同じ決まりで持つ。
- 再生で飛ばす曲は、ボタンを除いて薄くする。
- キューの行は同じ形で、ボタンの列を置かない。キューは狭い横のペインで、同じコマンドをキーとメニューで
  持つため。
- Songs は見出しで並べ替える表なので、曲名と詳細の場所を曲名、アーティスト、アルバムの列に分ける。見出しは
  `song_headings` で行と同じ列に置く。
- 行の高さは、カバーか 2 行目のある行で 48 px、1 行の表（Songs）で 40 px。

## 画面の言葉

言葉は画面の作りの一部。移動先、もの、コマンド、状態、結果の言葉を、1 つの体系として書く。その文脈で
正確なうちで一番短い言い方を選ぶ。英語の UI の言葉は今の GPUI 版の言い方を引き継ぐ。

### 文脈に文脈を任せる

周りの面がすでに言っていることを繰り返さない。移動先はもの自身の名前にする（`Albums`、`Playlists`）。
`Delete “Roadmap”?` と題したダイアログの本文で同じことを聞き直さない。AGENTS.md の「No self-evident text」
もこれを求める。

足すのは決定を変える言葉だけ：影響する範囲、取り返しのつかない結果、珍しい前提、戻り方。

移動先とものには名詞（`Artists`、`Appearance`）、コマンドには動詞（`Play`、`Rename…`）、状態には形容詞か
短い句（`Offline`）を使う。`Management`、`Page`、`Function`、`System` のような包みの言葉は、本当の領域の
概念を区別するときだけ使う。

### 言語ごとに書く

同じ意図、階層、用語から、それぞれの言語で自然な画面の言葉を組み立てる。元の言語の語順や語の数を写さない。
囲む情報の構造が与える言葉は省く。`Settings` の中のページは `Account Settings` ではなく `Account`。

繰り返し出るもの、コマンド、状態の言葉は小さな辞書として持ち、ツールバー、メニュー、コンテキストメニュー、
ダイアログで同じ言葉を使う。言葉は描いた画面の中で確かめる。

ドキュメントでは API、部品、ファイル、ガイドの名前を英語のまま書き、コードの書式にする。周りの説明は
そのページの言語で書く。

### 状態の言葉

読み込み中、失敗、空、絞り込みの結果無しは、どの画面も `next_ui::load_state` の辞書（`Subject` と
その定数、`NONE_ON_SERVER`、`no_matches`）で言う。画面ごとに言い回しを作らない。

| 状態 | 言い方 | 例 |
| --- | --- | --- |
| 待ち（アクセシビリティの名前） | `Loading <名前>`、`Updating <名前>`。名前はタイトルケース | `Loading Songs`、`Updating Library` |
| 失敗の見出し | `Couldn't load <もの>`、`Couldn't refresh <もの>` | `Couldn't load songs`、`Couldn't load this album` |
| 失敗の本文 | コアの理由。何が起きたかと戻り方を言い、見出しを繰り返さない | `Couldn't reach the server. Check your connection and try again.` |
| 空 | `No <もの>`。サーバーのライブラリにあるものは `No <もの> on this server` | `No playlists`、`No songs on this server` |
| 見出しの下の節の空 | 見出しがものを言うので `None on this server` | |
| 絞り込みの結果無し | `No matches for “<入れた言葉>”` | `No matches for “blue”` |

- 見出しと短い状態（待ち、空、結果無し）には句点を付けない。失敗の本文と補足（`Right-click a song to
  add it.`）は文なので句点を付ける。
- 同じ失敗を知らせとペインの両方で言うときは同じ言葉にする（`Couldn't refresh the library`）。
- 失敗にはいつも Retry を付ける。Retry で直らない理由は、本文で直し方を言う。
- Home のように、すべての節が同じ理由で失敗したら、節ごとに並べず、1 つの失敗と、すべてをやり直す
  Retry にまとめる。

### ボタンと確認のダイアログ

ボタンのラベルは短く、ふつうは 1、2 語で、手つきや部品ではなく結果を言う。`Click to save` ではなく
`Save`。決めずに出る操作はいつも `Cancel`。`OK` は知らせを受け取るだけのときに取っておく。

長いラベルは、言葉が結果を見せるか、取り違えやすい選択を分けるときだけにする（プレイリストから外す
`Remove from Playlist` と、プレイリストそのものを消す `Delete…`）。

| 文脈 | 弱い | 良い |
| --- | --- | --- |
| 消すダイアログ | `Yes`、`Sure`、`Confirm deletion` | `Delete` |
| 保存していない変更 | `Confirm`、`Yes` | `Discard` |
| 受け取るだけ | `Confirm operation` | `OK`、`Done` |

確認のダイアログは 1 つの小さな決定にする：

- タイトル：決定か状況（`Delete “Roadmap”?`）
- 本文：新しい範囲、結果、戻り方だけ
- 操作：`Cancel` と結果（`Delete`）
- 取り返しのつかない見た目は結果の操作に付け、正確な言葉の代わりにしない。見た目は error 色の文字ボタン
  （`next_ui::dialog_parts::irreversible_button`）で、`Cancel` はふつうの文字ボタンのままにする

`Notice`、`Warning`、`Error`、`Confirmation` のような一般のタイトルを避け、状況を名乗る。「Are you sure you
want to…」「Please note that…」「successfully」のような決まり文句を避ける。

### 大文字と句読点と記号

- コマンド（ボタン、メニューの項目、アイコンボタンの名前）は今の GPUI 版と同じく macOS のメニューの
  タイトルケースにする：`Add to Playlist`、`Go to Album`、`Sign Out`、`New Playlist…`。同じ種類の部品の中で
  揃える。
- 文、説明、エラーは文の形にする。
- ラベル、ボタン、メニューの項目、タブ、見出し、プレースホルダー、短い状態には終わりの句点を付けない。
  説明、警告、エラーの文には付ける。いつもの成功と失敗に感嘆符を付けない。
- 省略記号は 1 文字の `…` を使い、3 つの点にしない。ダイアログ、ポップアップを開くか、終えるのにさらに入力か
  選択の要るコマンドに付ける（`Settings…`、`Add Server…`）。すぐ走るコマンドには付けない。続いている仕事は
  点ではなく進み具合の部品で示す。
- エラーは何が起きたかと、役に立つなら次の戻り方を言う：
  `Couldn't reach the server. Check the address and your connection.`

### ロケールと macOS

- 表に出る言葉は英語。アクセシビリティの名前も英語のままでよい。ものに対する操作の名前には、そのものの
  ラベルを使う。
- 言葉は長い訳と日本語の字形に耐えるようにする。1 つの英語のラベルから部品の大きさを決めない。訳した
  かけらをつなげて文を作らない。
- ⌘ と Ctrl の違い、システムの外観、スクロールバーの振る舞い、メニューバーのように、意味を持つ macOS の
  約束を守る。

## AI が画面を変えるとき

いちばん近い画面、`next/ui` の部品、md3e の部品のソースと `docs/design/` を先に読む。コードを書く前に、
主な作業、状態の持ち主、部品の組み立て、キーの道筋を言う。React や GPUI の例、名前のもっともらしさから
API を推し量らない。

もっともらしい画面の絵は証明ではない。キー操作、フォーカス、変わる中身、テーマとカバーの配色、大きさを
変えること、失敗の状態もデザインの一部。人が、その階層、密度、部品の選び方、例外の値がなぜここに合うのかを
説明できるまで、AI の出したものは終わっていない。

## アクセシビリティのチェックリスト

スクリーンリーダーは AntiWebUI から届かない（決まったこと 6）が、名前と役割はテストのために付け続ける。

- どの操作もキーで届き、使える
- フォーカスの順が見た目と作業の順に沿う
- フォーカスが見え、オーバーレイのあとに戻る
- 部品に名前がある。アイコンだけの部品は `.access` で名前を付け、意味、範囲、キーの説明が要るときは
  ツールチップも付ける
- 見出しには `Role::Heading` と段を付ける
- 文字と意味のある境目に十分なコントラストがある。カバーから作った配色でも確かめる
- 状態を色だけで伝えない
- 無効と読むだけの状態を見分けられる
- ラベル、エラー、説明が部品のそばにある
- 長い訳と大きな文字でも使える
- 詰まった画面でも、ポインタの的が押しやすい大きさ

## レビューのチェックリスト

レビューは部品を数えるのではなく、画面が正しい決定をしたかを判じる。順に聞く：

1. **作業ははっきりしているか。** 初めての人が、目的、主な操作、次の一歩を、学ばず、当てず、試さずに
   分かるか。
2. **どの操作も約束を守るか。** ラベル、部品、状態、範囲、フィードバック、結果が 1 つの結果を言っているか。
3. **階層は決然として控えめか。** 主な機能がふさわしい場所を取り、強い色、太字、バッジ、塗りのボタンが
   少ないか。表現が再生を伝えるところに集まっているか。
4. **少なくして良くできないか。** 入口、選択肢、状態を、作業を弱めずに消すか、まとめるか、後に回せないか。
5. **構造は正確か。** 同じ段のものが揃う線を共有し、等しい間が 1 px まで等しく、スクロールバーが本当に
   スクロールする面の端にあるか。
6. **md3e の部品に従っているか。** 標準の部品が形、状態、キー、閉じ方を保ち、見た目は md3e のトークンから
   来ているか。デスクトップの密度が守られているか。
7. **どの状態とどの制約でも使えるか。** キーとフォーカス、空、読み込み、失敗、長い訳、最小のウィンドウ、
   ライトとダークとカバーの配色、動きを減らす設定。
8. **本物で確かめたか。** 本物の部品、言葉、それらしい中身で作業を終えてみたか。`shots` の例で描いた画面
   だけで終わらせない。

コードの書き方は[コーディングのガイド](coding-guide.md)に続く。

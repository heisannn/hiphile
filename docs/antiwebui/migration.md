# UI を AntiWebUI に移す

2026-11-12 に計画した。デスクトップアプリを GPUI と GPUI Kit から
[AntiWebUI](https://github.com/bea4dev/AntiWebUI) に移し、画面を `anti-webui-md3e` で Material 3
Expressive にデザインし直す。コアは [Extracting the core](../core/extraction.md) が残した形のままで、
ビューはコアのハンドルに従い、ビューの状態だけを持つ。[決まったこと](#決まったこと)は同じ日に決めた。

| | |
| --- | --- |
| 目標 | デスクトップアプリが AntiWebUI と `anti-webui-md3e` で動き、Material 3 Expressive でデザインし直されていて、ワークスペースに GPUI が残っていない |
| 規模 | gpui-kit に依存するクレートは 14 個。ビューは約 17,100 行、そのテストは約 8,500 行（`#[gpui_kit::test]` が 260 個）。コアのクレートのテスト 378 個が `gpui-host` を通して GPUI の executor で動いている |
| 対応する環境 | macOS 14 以降だけ（arm64 と x64）。Windows はあとで戻す。それまで Windows と macOS 12・13 は GPUI 版の最後のリリースに留まる |
| 大きな不足 | メニューバー、アプリから取れるウィンドウハンドル、ウィンドウの位置・最前面・最小サイズ、キーバインド、テキストの省略記号が無い。仮想リストの行の高さは 1 種類だけ |
| 大きなリスク | AntiWebUI は 10 日目（最初のコミットは 2026-11-02、70 コミット、作者 1 人、CI なし）。ネイティブのメニューは AntiWebUI がやらないと決めている |
| 順序 | 検証、テスト用 executor と AntiWebUI の修正、土台、プレーヤー、各画面、歌詞と設定、パリティ、切り替え（[手順](#手順)） |
| GPUI 版と並べて作る | 新しいアプリは `next/` で育て、パリティに届くまで GPUI 版のリリースを続ける。2 つは 1 つのウィンドウもイベントループも共有できない |

## 調べた時点の AntiWebUI

`25e82a1`（2026-11-11）を読んだ。この節のパスは AntiWebUI のリポジトリからの相対パスで、`dNN` は
その `docs/design/NN-*.md` を指す。

### 合うところ

- **コアの形。** AntiWebUI のシグナルはスレッドローカルで細粒度に更新される。コンポーネントの関数は
  一度だけ走り、クロージャは読んだシグナルが変わったときに走り直す（d02）。コアはすでにスナップショットを
  `watch` に、通知を `broadcast` に出している（コアのルール 3）ので、ビューはそれぞれをシグナルに
  変えればよく、コアがどう動いているかを知らなくてよい。
- **UI スレッドへの受け渡し。** `ui_channel(f) -> UiSender<T>`（`anti-webui-core/src/channel.rs:94`）は
  `Send` な送り口を返す。送るとループが起き、`f` が UI スレッドで batch の中で走る。
- **終了。** `App::run` は最初のウィンドウが閉じると戻り、⌘Q や Dock の「終了」はそのウィンドウへの
  閉じる要求になる（`anti-webui-macos/src/app.rs:30-37`）。`main` は `run` が戻ったあとメインスレッドで
  `Hiphile::shutdown()` を呼べばよく、フックは要らない。
- **カバー。** `img` はファイルのパスかバイト列を受け取り、描く大きさでワーカースレッドがデコードし、
  デコード済みの絵を 256 MB まで持つ（d22）。カバーは `CoverStore` のファイルをパスで渡す。これで
  `ui::NetHttpClient` と `ui::CoverCache` が要らなくなり、認証情報も UI に出ない。
- **長いリスト。** `virtual_list` は見えている行だけを作る。10 万行の表のスクロールは 1 フレームの中央値が
  0.16 ms（d21:139）。行が使い回されてもドラッグは続く（d23:89）。
- **md3e。** 形が変わるボタン、ボタングループ、アイコンのトグル、FAB、ナビゲーションレール、タブ、トップ
  アプリバー、検索、サブメニューのあるメニュー、ダイアログ、シート、スナックバー、ツールチップ、スライダー
  （通常、中央、範囲、波線）、プログレス（線、円、波線）とローディングインジケーター、パスワードの使える
  テキストフィールド、チップ、カード、カルーセル、リスト、34 の表現的な形、軸をアニメーションできる
  Material Symbols、モーションのトークンがある。配色は実行時に種の色からすべてのスキームバリアントで作れ、
  `dynamic::seed_colors` は画像のピクセルから種の色を見つける。つまり再生中の曲のカバーに配色を合わせ、
  `set_color_scheme_animated` でクロスフェードできる。
- **テスト。** `core::Ui` はウィンドウなしで合成イベントとフレームを受け取り、
  `accessibility::snapshot()` は役割と名前でノードを探し、`app::headless` は PNG を描く。
- **依存関係。** このワークスペースに試しのクレートを作り、`anti-webui`（macOS、Windows、SVG）、
  `anti-webui-md3e`、`desktop` を有効にした `hiphile-core` をリンクした。ロックは 33 パッケージ増えた
  だけで、既存のバージョンは変わらなかった。このマシンの温まったキャッシュで 25 秒でビルドできた
  （まっさらなビルドは測っていない）。GPUI はすでに Linux 向けに wgpu 30 をロックしている。

### 足りないところ

### ここでビルドして分かったこと

- **小数のリテラルが CI で落ちる。** スタイルのメソッドは汎用の長さを受け取るので、`.p(16.0)` は
  将来非互換の lint `float_literal_f32_fallback` のもとで `f32` に落ちる。CI と同じ
  `cargo clippy -- -D warnings` では、試しのクレートの `.p(16.0)` 1 つがエラーになった。AntiWebUI 自身の
  クレートでもこの lint が 287 回出たが、cargo は git 依存の lint を抑えるので、ここでは問題にならない。
  フォークで長さに `From<f64>` を足すか、`16.0_f32` と書く。
- **macOS で 1 つのスレッドにウィンドウが 2 つあるとスタックがあふれうる。** macOS の `Session` には
  `request_redraw(key)` と `redraw_pending(key)` が無い。そのため runner のトレイトのメソッドが自分自身を
  呼ぶ（`anti-webui-app/src/runner.rs:688-693`、rustc の `unconditional_recursion`）。`redraw_changed`
  （`:867-876`）はスレッドにウィンドウが 2 つあるといつでもそこに届く。メインウィンドウの横に開く設定の
  ウィンドウとミニプレーヤーが当てはまる。実行はしていない。step 4 より前にフォークで直す。

## 構成

### クレート

2 つのアプリがワークスペースにある間、新しいクレートは `next/`（`members` の 2 つ目のグロブ）に置き、
パッケージ名が重ならないよう `next-` を付ける。切り替えのときに `crates/` へ今の名前で移す。

| クレート | 置き換えるもの | 持つもの |
| --- | --- | --- |
| `next-host` | `gpui-host`、`ui` の HTTP クライアントとカバーのキャッシュ | アプリの tokio ランタイムとその上の `Spawner`。`follow`、`notices`、`on_ui`。`img` に渡すカバーのパス |
| `next-platform` | GPUI の `set_menus` | macOS のメニューバー、フォークが持つまでの外観。デスクトップ専用で、`hiphile-core` の下には入れない |
| `next-ui` | `ui`、`actions` のメニューとグローバル | テーマとトークン、キーマップ、画面をまたぐコマンド、共通の部品 |
| `next-account`、`next-home`、`next-library`、`next-artists`、`next-songs`、`next-playlists`、`next-favorites`、`next-search`、`next-player`、`next-settings` | 同じ名前のクレート | 1 つの画面、パネル、ウィンドウずつ。テストは `<view>/tests.rs` |
| `next-hiphile`（バイナリ `hiphile-next`） | `hiphile` | 起動、シェル、ルーティング、メニューバーのコマンド |

`actions` は無くなる。その struct のアクション（`ShowAlbum`、`AddToPlaylist`、`PlaySongs` など）は
`Command` の enum になり、シェルが処理し、画面は渡されたハンドルを通して送る。3 つのグローバル
（`PlaylistChoices`、`KnownFavorites`、`SkipInstrumentals`）はもともとコアのスナップショットの写しなので、
シェルが一度だけ従うシグナルになる。

### スレッドと状態

- コアは `main` が作るマルチスレッドの tokio ランタイムで動き、`Executor::tokio` として渡される。`net` は
  自分のランタイムを持ち続ける。`main` は `run` が戻ってランタイムを止めたあとで最後の `net::Client` を
  落とし、ランタイムの中では落とさない（コアのルール 11）。
- ビューは `next-host` を通して `watch` をシグナルに変える。橋渡しのタスクはビューのオーナーと一緒に止まる。
  スケッチ：

  ```rust
  pub fn follow<T: Clone + Send + Sync + 'static>(
      executor: &Executor,
      mut changes: watch::Receiver<T>,
  ) -> Signal<T> {
      let value = signal(changes.borrow_and_update().clone());
      let to_ui = ui_channel(move |snapshot: T| value.set(snapshot));
      let task = executor.spawn(async move {
          while changes.changed().await.is_ok() {
              to_ui.send(changes.borrow_and_update().clone());
          }
      });
      on_cleanup(move || drop(task));
      value
  }
  ```

  `notices` は `broadcast` に対して同じことをし、`Lagged` は飛ばす。`on_ui(task, f)` はコアの
  `executor::Task<R>` を待ち、オーナーが残っていれば `f` を UI スレッドで走らせる。これらが `observe`、
  `observe_in`、`subscribe`、`subscribe_in`、`notify_on_change`（合わせて 43 か所）を置き換える。
  スナップショットは出されてから UI スレッドの次の回にシグナルへ届く。呼び出しの結果をすぐ見せるビューは、今と同じく
  呼んだ直後に `snapshot()` を読む。
- シグナルはスレッドをまたがない。`Signal<T>` は ID だけなので `Send` になってしまうが、ランタイムの無い
  スレッドで使うとパニックし、別の UI スレッドでは同じ ID が別の値を指しうる。UI スレッドの外のコードは
  シグナルではなく `UiSender` を持つ。
- 再生位置は出されない（step 7 のコアの決定）。プレーヤーバーは 250 ms ごと、歌詞は 50 ms ごとに
  `position()` を読む。今と同じで、見えている間 `set_timeout` をかけ直す。一定間隔のタイマーは無い。

### キーとメニュー

- `next-ui::keymap` はバインドを `(キーストローク, コマンド, コンテキスト)` で持ち、macOS では ⌘、それ以外
  では Ctrl を使う（`Modifiers::primary`）。コンテキストは `key_context(name)` を付けた要素で、そのハンドラは
  そのコンテキストのバインドのうち、そこで有効なコマンドのものを使って伝播を止める。こうして GPUI と同じく
  内側のコンテキストが勝つ。どこでも効くのは「終了」と「設定」の 2 つ。
- コマンドの有効・無効は memo で決まる。シェルは今と同じく、使えるときだけコマンドを登録する
  （`app_shell.rs:1231-1355`）。メニューバーは同じ memo を読んで項目を有効にし、チェックを付け、`effect` で
  作り直す。ツールチップとメニューにはキーマップのキーストロークを出す。
- メニューバー（`next-platform`）は今と同じ 4 つ：hiphile、Library、View、Controls。項目は `Command` を
  `UiSender` で送るので、AppKit のコールバックの中でリアクティブなコードは走らない。

### ウィンドウ

| ウィンドウ | 要るもの |
| --- | --- |
| メイン | 保存した位置で開く（新しく足す）。最小 900×560。閉じると終了する。タイトルバーは中身の上で、信号機ボタン付き |
| 設定 | 一度に 1 つ。開いていれば前に出す。最小 560×360 |
| ミニプレーヤー | すべてのアプリより前。フォーカスを取らない。最小化できない。位置とディスプレイを覚える。最小 260×320 |

3 つともメインスレッドで `open_window` で開くので、シグナルと配色を 1 つずつ共有する。上の macOS の
再描画の修正を待つ。

### テスト

- ビューのテストは `hiphile_core::test_support` の偽のサーバーを使ってビューを `core::Ui` に載せ、合成
  イベントを送り、`accessibility::snapshot()` でノードを探す。22 個の `debug_selector` は名前か役割になる。
  タイマーやばねを待つテストには差し替えられる時計が要る。それまでは時間ではなく状態を確かめる。
- `gpui_host::executor(cx)` で動くコアのテスト 378 個は先に `executor` の決定的な executor へ移す。
  シングルスレッドで `run_until_parked` と `advance_clock` を持ち、GPUI と同じくブロックする仕事をその場で
  走らせるので、テストの本体は形を変えずに済む。`extraction.md` がこれを予定していた（"Should GPUI go"）。
- CI は `macos-latest` でヘッドレスのビューのテストを走らせる。そこに GPU のアダプタがあるかは step 0 で
  確かめる。

## Material 3 Expressive での再デザイン

デスクトップのプレーヤーとしての Hiphile の良さは残し、見た目を MD3E に移す。キーボード、詰まった
リスト、メニューバー、コンテキストメニュー、大きさを変えられるペイン、コマンドのそばに出るショートカットは
残す。表現は再生を伝えるところに使い、ライブラリの長いところは詰めたままにする。

| 色 | md3e の `ColorScheme` を種の色から `SchemeVariant::Content` で作る。種は再生中の曲のカバー（約 128 px に縮めたカバーにタスクで `dynamic::seed_colors` をかける）が既定で、Appearance で固定の色も選べる。曲が変わると `motion::slow_effects` で配色をクロスフェードする。Light、Dark、System は今と同じ。テーマの外に色のリテラルを書かない |

| 動き | md3e のばね（`fast`、`default`、`slow` × `spatial`、`effects`）。画面は md3e のショーケースと同じく、薄く現れて少し上がって入る。すぐ終わる操作では何も動かさない |

### ガイド

gpui-kit のスキルと AGENTS.md の最初の節は切り替えのときに外す。代わりの 2 つのガイドを step 3 で書く。

- **デザイン。** 上の決まりと、何にどの md3e の部品を使うかを、詰まったデスクトップアプリ向けに書く。今の
  ガイドのうち GPUI Kit に依らないところは残す：作業から始める、状態は見えるようにする、モバイルより
  デスクトップの約束を先にする、画面の言葉、アクセシビリティとレビューのチェックリスト。
- **コーディング。** コンポーネントの関数は一度だけ走る。変わるものはクロージャにする。シグナルは自分の
  スレッドから出さない。ビューは `next-host` を通してコアに従う。オーバーレイは `open` と `on_dismiss` を
  持つ子として置く。md3e の色は `dyn_style` の中で読む。md3e と prelude は名前（`button`、`switch`）が
  重なるので、名前を明示して import する。テストは上のとおり。

### 更新

updater は最新のリリースのバージョンだけを見て更新の有無を決め、自分のプラットフォームのアセットは
入れるときにしか探さない（`updater/src/install.rs:92-98`）。step 7 のリリースが無いまま切り替えると、
macOS 12・13 の GPUI 版はそこで起動しないビルドを入れてしまい、Windows の GPUI 版は入れられない更新を
6 時間ごとに見つける。そこで step 7 のリリースでは、自分のプラットフォームのアセットがあり、macOS では
この版で動くときだけ更新ありとみなす。AntiWebUI 版の macOS のアセットは `-macos14-arm64.zip` のように
名前に最小のバージョンを持ち、macOS 14 以降の GPUI 版はその名前を探す。

## 決まったこと

2026-11-12：

1. **AntiWebUI はフォークする。** Hiphile はリビジョン固定でフォークに依存する。フォークの変更を上流に
   送るかは保留。このアカウントはリポジトリに push できない。
2. **タイトルバーは中身と一体のまま。** フォークに、全面に広げた中身の上に信号機ボタンを残すモードを
   足す。ウィンドウのボタンを自分で描くことも、標準のタイトルバーにすることもしない。
3. **最小は macOS 14。** そこからはフレームの間隔の調整が正しく動く。
4. **はじめは macOS だけ。** Windows のために GPUI を残すことはしない。切り替えから AntiWebUI 版が
   Windows に対応するまで、Windows の利用者は GPUI 版の最後のリリースに留まる。対応には Win32 での
   HWND、ウィンドウの重なり、フォーカスを取らないウィンドウ、手での IMM32 の確認、Windows のフォントが要る。
5. **配色は既定でカバーから作る。** 固定の種の色も選べる。
6. **スクリーンリーダーは無くてよい。** AntiWebUI に橋渡しができるまで VoiceOver には何も届かない。

## リスク

- **成熟度。** AntiWebUI は作者 1 人の 10 日分の仕事で、CI が無く、多くは合成イベントでしか確かめられて
  いない。macOS でのライブリサイズ、日本語の入力、トラックパッド、⌘Q、全画面は手で確かめられていない
  （d38:339-345）。リビジョンを固定し、更新は意図して行う。
- **範囲。** ネイティブのメニュー、シート、ネイティブのコントロールは AntiWebUI がやらないと決めている。
  フォークが入れないものは `next-platform` が持つ。
- **フォーク。** 上流の更新はそのたびにフォークへのマージになり、フォークが変わるほど増える。
- **Intel。** AntiWebUI では試されていない。
- **取り残される利用者。** macOS 12・13 と Windows は GPUI 版の最後のリリースで止まる。
- **デスクトップでの MD3E。** md3e の部品はタッチ向けの大きさ。詰まったリスト、表、設定には Hiphile の
  寸法が要り、デザインのガイドがそれを守らせる。
- **テスト。** 260 のビューのテストは移すのではなく書き直しになり、時計を差し替えられるまでタイマーを
  進められない。
- **大きさ。** Roboto Flex で約 1.8 MB、アイコン 1 つで約 3 KB 増える。SVG の文字を有効にすると 1.6 MB。
  Roboto Flex の OFL と、Material Symbols の Apache ライセンスと NOTICE をアプリに同梱する。
- **2 つのアプリを同時に持つこと。** step 3 から 7 の間に GPUI のビューを直すと、二度直すことになる。
  直すのはバグだけにする。

## 完了の条件

- gpui に依存するクレートが無く、コアのクレートを守るチェックがどの UI フレームワーク（`gpui*`、
  `anti-webui*`）でも失敗する。
- AntiWebUI 版で、macOS 14 で[パリティ](#パリティ)が満たされている。
- CI がフォーマット、`-D warnings` の clippy、ヘッドレスのビューのテストを含むテスト、チェックを走らせる。
- リリースが macOS の arm64 と x64 向けにビルドとパッケージングをし、GPUI 版の最後のリリースは macOS 14
  以降ではそこへ自分で更新し、それより古い macOS と Windows ではそのまま留まる。
- デザインとコーディングのガイドが gpui-kit のスキルを置き換え、AGENTS.md がそれを指している。
